Given n non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining.


Input: height = [0,1,0,2,1,0,1,3,2,1,2,1]
Output: 6
Explanation: The above elevation map (black section) is represented by array [0,1,0,2,1,0,1,3,2,1,2,1]. In this case, 6 units of rain water (blue section) are being trapped.
Example 2:

Input: height = [4,2,0,3,2,5]
Output: 9
 

Constraints:

n == height.length
1 <= n <= 2 * 104
0 <= height[i] <= 105
 








=========================================






Answer


Approach : 

“So, at every index, water can be trapped only if there are taller bars on both sides.
The amount of water trapped at i depends on the minimum of max heights on both sides minus the height of the bar itself.”

Brute Force :
At every index:
Find maxLeft (tallest bar to the left)
Find maxRight (tallest bar to the right)
Water trapped = min(maxLeft, maxRight) - height[i] if positive.
Time: O(n²)


Slight optimized :
Instead of recalculating left/right max for each element, precompute them once.
💡 Idea
leftMax[i] = max height to the left of i
rightMax[i] = max height to the right of i
Water at i = min(leftMax[i], rightMax[i]) - height[i]
Time: O(n), Space: O(n)


2 Pointer approach :
Time: O(n), Space: O(1)


Code snippet :

class Solution {
    public int trap(int[] height) {
        int left = 0, right = height.length - 1;
        int leftMax = 0, rightMax = 0, trapped = 0;

        while (left < right) {
            if (height[left] < height[right]) {
                if (height[left] >= leftMax)
                    leftMax = height[left];
                else
                    trapped += leftMax - height[left];
                left++;
            } else {
                if (height[right] >= rightMax)
                    rightMax = height[right];
                else
                    trapped += rightMax - height[right];
                right--;
            }
        }
        return trapped;
    }
}







Q1 Why move the smaller height side first?
Because the trapped water is limited by the smaller boundary; whichever side is smaller determines the water level possible at that moment.

Q2 What if the heights are all increasing or decreasing?
Then no water can be trapped — your algorithm still returns 0 correctly.

Q3 Can this be solved using a stack?
Yes — a monotonic stack can also compute trapped water in O(n) (advanced alternative).
